# Hard-coded feel numbers — Runtime audit

Source: `main` at `96264e13187659d90dba198703bba188721f4e23`. Folder: `unity/Assets/OrbitalAnte/Scripts/Runtime/`. This is a source-only inventory for Claude to check and Fable to prioritize, against `CLAUDE.md` Part A's config-asset convention. It changes no code, config, standing rules or tuning and proposes **no replacement numeric values**. No Unity run or playtest is claimed.

Paths below are relative to the audited Runtime folder; line numbers belong to this SHA. “Proposed owner” means a possible field/group in the existing asset, not a direction to add an asset or a design decision. Exposing a number is not permission to retune it. Keep current values and behavior if Claude/Fable choose a later extraction. The ranking estimates the relevance to player feel, not measured severity or a quality-gate verdict.

The main snapshot has no `Ship/` or `Look/` runtime folders: their code is on pending PRs #6/#8, outside this audit's base. Existing asset defaults in `PlayerConfig`, `MannequinConfig`, `GoreConfig`, `TestCraftConfig`, `WeaponData`, `PlanetData/PlanetSettings`, `PlanetProfile`, `BodySpec` and `SolarSystemData` are already data-defined; a numeric literal in one of those defaults is not itself a config violation. ## Keep source constants that express structure, mathematics or authored geometry

- `Weapons/FirearmState`'s `1 / ShotsPerSecond`, ammo decrement, hand count zero/one/two and timer clamping express rules/math; fire rate, reload seconds, bloom, recoil and one-hand multipliers already originate in `WeaponData`/`FirearmSpec`. They are not missing tuning merely because the pure model repeats arithmetic constants.
- RNG hash/mix constants, mesh triangle indices, channel counts, axis conversion, radians/degrees conversion, Coriolis factor `−2`, midpoint-integrator factor `0.5`, tolerances preventing division by zero, serialization version/format identifiers and physics layer numbers belong in code. Do not expose them as gameplay sliders.
- The mannequin rig's pose angles, limb proportions and placeholder collider/body dimensions need a shared geometry/animation contract if revised. The locomotion pulse and blocker rows above identify the pieces affecting movement/collision; this audit does not request turning every bone angle into a feel control or editing Fable's assets.
- `WeaponModelFactory` sockets/model dimensions, `TestArena` cover layout/arena size and `BodyLayout` hierarchy are authored geometry/scenario structure. They can affect a test arena experience, but are not hidden damage/speed/timer values. A data-driven scenario is a separate design/engineering scope, not demanded here.
- `PlanetProfiles.Defaults`, `SolarSystemDefaults`, `BodySpec`, `PlanetProfile`, `FormationUse` and the formation index are data/default construction. Terrain-noise shape coefficients in `PlanetTerrain`/`FeatureShapes`/`CavePath` and water visual coefficients in `PlanetSurface` are predominantly generation/art algorithms; do not indiscriminately externalize them as feel tuning or replace them in this task. The identified atmosphere, wind and collision values are the clearer handling/readability candidates.
- Pools, work limits and tessellation values (`GoreFx.MaxBleeders`, weapon tracer/flash/mark counts, weather particle cap, `PlumeFx.MaxActive`, LOD mesh segments, job worker/upload budgets) are primarily performance policy; consider them alongside `docs/performance_budget.md`, not as feel values. They need separate cap/lifecycle review before any change. Existing configurable caps are already assets.
- UI layout pixels/colours, sample rates, audio waveform coefficients, cosmetic noise grain, renderer queue and shader-property IDs are not the focus of a speed/damage/timing/force extraction. A palette or sound profile remains Fable's decision. Existing hard-coded feedback lifetimes and response curves were retained in the lower-priority inventory because they directly shape event readability.

## Suggested review procedure for Claude and Fable

1. Decide which rows merit data ownership; start with the collection/disarm and physical-response values that complement existing config fields.
2. If a later extraction is approved, keep every existing value and clock domain unchanged. Record semantic groups and shared invariants so two related defaults cannot drift independently.
3. Have Claude check behavior-preserving changes with rule/PlayMode coverage where applicable. Ask Fable to assess the same seeded scenario with the same inputs; this report contains no playtest result or recommended retune.
4. Keep this audit separate from new features, physics redesign, asset generation, faction naming and Phase 2 work. Main's pending Ship/Look additions need a fresh source-anchored inventory after they merge.
